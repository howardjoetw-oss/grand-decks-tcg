# GRAND DECKS — 一次規劃、整合開發藍圖（v3–v9）

**確定的產品定位：** 以 ONE PIECE TOP DECKS 的世界賽事／優勝牌組情報為參考，製作獨立的、繁體中文優先的 ONE PIECE CARD GAME 競技 PWA。網站本身提供可更新的卡牌搜尋、來源可追溯的熱門／優勝牌組、組牌、Meta 與牌組分析。**不是 OPTC，也不是卡牌收藏管理站。**

## A. 不可改變的共通原則

1. **來源優先、證據分級：** 正式平台成績、第三方賽事報告、社群玩家自述必須區分；「個人 7 勝 0 敗」不等於「全球牌組勝率 100%」。
2. **卡表永遠以目前有資料的最新版本為目標：** 每日比對上游索引與 TOP DECKS 系列清單。卡號為主鍵，異圖版本不當作不同牌組卡號；記錄最後成功同步／最後嘗試／來源最後更新。可先有未來預告卡，必須標為「預告、尚未正式發售」。
3. **資料保存：** 新資料不合格或來源失敗時保留上一份成功快照，不讓空白或錯誤 JSON 覆蓋。所有原始事件、單張牌與牌組有穩定 ID、變更記錄及可回溯來源。
4. **不虛構資料：** 沒有牌組清單就不產生假的 50 張；沒有公開戰績就顯示「未公開」；不能將勝率、上位率、登場率混稱。
5. **純免費優先：** Cloudflare Pages Free + GitHub 公開儲存庫 Actions；不購買網域、不中途升級、不啟用計費 X API。功能若開始需要付款，先停止並取得使用者確認。
6. **合規：** 尊重 robots、平台條款、API 額度、著作權和商標。TOP DECKS 系列頁可以監看候選系列，不代表獲准鏡像完整卡圖／卡面文本。未有再利用依據時先保存基本識別資料與官方／來源連結，不大量複製影像和全文。
7. **單次公開部署：** v4–v9 可內部開發、測試、整合；對使用者以一次總整合包／單次 GitHub 更新與 Cloudflare 部署為主要流程，不要求每版反覆重新部署。
8. **手機優先：** Android Chrome、PWA 安裝、手機按鈕、低網速，以及離線已讀資料。備份／還原必須保留既有私人牌組。

## B. 共用架構（所有版本只建一套）

```text
資料來源（官方公開賽事 / Limitless / TOP DECKS / 公開論壇與提交）
    ↓ 來源政策、限速、抓取、資料結構驗證
來源轉接器 adapters/（API 優先；網站須合法且可穩定解析）
    ↓ 一致欄位 + 來源證據 + 穩定 ID
整併 / 去重 / 新舊版本比對 / 快照保留
    ↓ 靜態資料 public/data/*.json
GitHub Actions 定期更新 → Git commit（只在有必要時）
    ↓
Cloudflare Pages (Free) → PWA
    ↓
圖鑑 / 賽事牌組 / Meta / 牌組比較 / 組牌 / 社群候選
```

**建議基本資料實體：** `cards`, `printings`, `sets`, `events`, `event_results`, `deck_lists`, `deck_cards`, `source_records`, `community_candidates`, `sync_runs`, `rulesets`。先用有版本的 JSON；資料量或查詢成本超過合理規模，才評估 D1／Workers，但啟用付費方案前必須重新確認。

**重要 ID：** `card_base_id` 如 `OP17-039`、`printing_id` 如 `OP17-039_p1`、`event_id`、`entry_id`、`deck_fingerprint`（排序後 50 張主牌+領航員的雜湊）。同一套牌在不同賽事出現，應保留多筆賽事成績，但可歸到同一張構築指紋作比較。

## C. 分版規劃（目前 v3；其後 6 個開發模組）

### v3 — 最新卡表 + 優勝牌組同步基礎（目前工作版）

- [x] GitHub Actions 排程、Cloudflare 靜態網站架構。
- [x] 從第三方公開繁中卡號索引正規化名稱、顏色、費用、類型、能力數值；異圖去重。
- [x] TOP DECKS Cards 頁系列標籤監看程式（robots 禁止或抓取失敗時保留舊版）。
- [x] 發布 `cards.json`、`sync-status.json` 與 `topdecks-sets.json`；前端能自動載入最新已發布卡表，手動重新讀取。
- [x] 完整 50 張比賽牌組可複製或帶入組牌工作室作研究副本。
- [x] 基本解析單元測試、JS 靜態語法檢查。
- [ ] 必須在使用者 GitHub Actions 真實執行一次，以確認第三方可用性、網站授權與 Cloudflare 發布；未完成前不可宣稱「每天穩定自動更新」。

### v4 — 全球資料來源平台（收集穩定性）

**交付內容：** 統一 `adapter` 介面；Limitless API、TOP DECKS 比賽頁與其他合法公開賽事頁分別接入；依日本／台灣／北美／歐洲標籤區分資料；新增新舊資料差異檢查、重複來源辨識、重試／限速／失敗回復與來源健康狀態。

**驗收：** 同一套資料重跑兩次不增加重複牌組；任一來源失敗其餘來源仍可更新；沒有 50 張的結果可列出但不能匯入完整牌組；每筆資料保留來源 URL、抓取日期、來源類型。

### v5 — 可信的熱門與 Meta 分析

**交付內容：** 時間窗（7／30／90 天）、地區與卡包環境篩選、領航員上位次數與佔比、冠軍數、各賽事規模、近幾期使用趨勢；勝敗數若非同一統計口徑不得聚合成「全球勝率」。Meta 排名可提供「近期上位熱度分數」但必須說明計分公式，且與真正勝率分開。

**驗收：** 每個百分比有分子、分母；不足樣本顯示警示；不同時期禁限卡環境不能默默合計；測試資料集有固定預期結果可核對。

### v6 — 社群熱門牌組情報站

**交付內容：** Reddit、公開 YouTube、玩家投稿的來源連結蒐集；X 僅在免費且合法可存取的範圍採用連結／人工提交，不啟用付費 API。候選牌組標示「待查證」、提及數、轉載重複、公布日期、來源連結。建立反灌水與跨帖去重。

**驗收：** 社群牌組不會自動進入「已驗證高勝率」；缺完整牌表時仍能收藏來源但不生成卡牌；任何 URL 都可追溯，檢查有無重複提交。

### v7 — 競技組牌＋牌組比較

**交付內容：** 一鍵複製來源賽事牌組、兩套牌組並排差異、同領航員多版本比較、張數與卡色驗證；增加按日期／賽區套用禁限卡與例外規則的介面。手機上逐張增減、搜尋和排序不用反覆跳頁。

**驗收：** 50 張主牌與 1 張領航員可驗證；同卡號的異圖併入相同四張上限；發現不合法牌組時給出明確原因；匯入與個人牌組不會無提示地覆寫。

### v8 — 高效率手機 PWA 與使用體驗

**交付內容：** 首頁最新賽事、領航員圖鑑快速篩選、卡號與繁中關鍵字搜尋、牌組收藏／最近查看、快速比較、來源可信度圖示、離線最近資料、資料快取更新提示。優化大卡庫與清單效能、Android Chrome 安裝流程、繁體中文閱讀體驗。

**驗收：** 手機可完成「找領航員→看前八牌組→複製→比較→儲存」單一路徑；離線時清楚標記快照日期；版本升級不會清空私人牌組；Android 直向畫面不會橫向溢位。

### v9 — 可靠度、維運、正式整合發布

**交付內容：** 全站端到端測試、資料完整性檢查、同步失敗報表與 GitHub Actions 內可見的錯誤定位、快照備份與還原操作、套件版本鎖定、安全性檢查、資料來源與免責資訊、Cloudflare 部署 SOP、完整的手機驗收清單與 README。

**驗收：** 先在 GitHub Actions 成功執行所有測試與同步，再部署 Cloudflare；無缺檔或 404；公開資料每個數值可回溯；使用者個人牌組備份／還原測試通過；不產生費用。

## D. 一次整合前的共通驗收清單

1. 新卡出現後能檢查／新增；上游失敗時舊卡仍可搜尋。
2. 新賽事與同賽事更新能去重；時間、地區、冠軍／前八篩選正確。
3. 牌組 50 張驗證與來源對照通過；點來源可以核對。
4. Meta 勝率、上位率、人氣三者名稱與分母正確。
5. X／Reddit／影片中的自述戰績**不標記為已驗證**。
6. Android 平板與手機都能安裝 PWA、開啟、搜尋、儲存。
7. GitHub 手動同步與每日排程可確認實際運行；網路中斷不會清空資料。
8. 無費用、無未授權的付費 API、無帳密洩漏；對第三方素材維持合法使用方案。

## E. 開發與交付策略：不逐版請你部署

- **目前:** 完成 v3 程式基礎與全部六個後續模組的規格；未連接你的個人 GitHub 或 Cloudflare 帳號，未執行線上部署。
- **下次整合工作:** 依本藍圖在同一個專案目錄連續完成 v4–v9，所有開發模組互相共用同一套 ID、資料 schema 與 UI 導覽，避免反覆重寫。
- **交付:** 一個最終 ZIP（包含可部署網站、資料同步程式、單元測試、SOP、已知限制），而非要求你下載六次不同版本。
- **正式發布:** 使用者確認最後一次部署步驟，再操作自己 GitHub／Cloudflare。若資料使用條款或免費額度構成障礙，應明確標記為未完成，不能宣稱已上線。

## F. 已知風險與替代做法

- **TOP DECKS／其他站的著作權及 robots：** 無可用授權時只監看允許讀取的系列資訊、保留來源網址，不鏡像受保護卡圖／文章。
- **免費 API／GitHub 定時工作可能中斷：** 建立來源健康狀態與手動重新同步，保留上一次成功資料。
- **賽事不同地區／卡表語言差異：** 卡號匹配為主；繁中卡表沒有收錄的顯示原始語言及缺卡標記。
- **來源熱門度偏差：** 將賽事上位、牌組採用、社群熱度分頁顯示，不當作統一高勝率。
